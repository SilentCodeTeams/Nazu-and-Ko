# Control API (design)

The daemon API is the only boundary between the Qt client and the backend.
The UI never links nettool-proxy or nettool-capture.

## Transport

Phase 2 starts with loopback TCP and a bearer token:

    bind 127.0.0.1:0
    write the chosen port and token to a 0600 state file
    JSON lines in both directions
    one persistent event subscription per client

The state file is line-oriented:

    port=53421
    token=0123456789abcdef0123456789abcdef

Later phases can add a Unix domain socket / Windows named pipe without changing
the message model.

## Authentication

- The token is generated by the daemon, stored in the state file with 0600.
- Every request carries the token.
- No remote bind by default. Remote access would require explicit configuration
  and TLS, and is not part of Phase 2.

## Commands

    start_proxy    listen, target, protocol
    stop_proxy     session id
    list_sessions
    subscribe      from event id
    acquire_mac    interface, requested identity, dry_run
    release_mac    lease id
    list_leases
    shutdown       daemon (helper keeps leases unless explicitly released)
    shutdown_helper release all leases and stop the helper

The first Phase 2 server slice implements:

- list_sessions (returns an empty list until proxy sessions are wired)
- acquire_mac with dry_run=true only
- release_mac
- list_leases
- shutdown

start_proxy, stop_proxy, subscribe and shutdown_helper are parsed by the
protocol but return "not implemented" until the next slice. acquire_mac without
dry_run also returns an error because the privileged helper is not present.

## Events

    packet         id, direction, protocol, length, dropped
    session        started, stopped, error
    mac_lease      acquired, releasing, released, error
    helper         status, version

Packet events intentionally carry summaries, not full payloads, on the control
channel. Full captures stay in pcap files requested by the client.

## Versioning

- The first message carries api_version.
- Unknown fields are ignored.
- Breaking changes bump the major version and the daemon refuses older clients
  with a clear error.

## Crate boundary

The message types live in crates/nettool-control, independent of the proxy.
The daemon translates events; clients never depend on proxy internals.
